## 1. Boundary-Aware Policy Learning (2611.32238): no fit for the picker; same Ion and coordinator gap as Delegent

This row asks that workers publish the start states they handle, and that the orchestrator check those states before handing a step off. That is not an input to `decide_step_model` (`impulse-rs/src/agent/step_model.rs:120`). The picker names one model per chat step. It does not consult a worker start-state contract, and `HarnessStepContext` (`step_model.rs:23-33`) has no such field.

There is still no per-subtask delegation point, as in the Delegent verdict in the Loop 162 note. Ion's tool bridge runs tools directly through `ToolRegistry::execute` (`impulse-rs/src/ion_repl/tool_bridge.rs`). The coordinator only notices delegations that already happened inside coding-CLI panes: `detect_delegation_events` (`impulse-rs/src/agent/coordinator.rs:411` on main 921f5c9, line 397 at 2ba676d) emits `RecommendationType::DelegationReady` (`coordinator.rs:91` on main, line 76 at 2ba676d) when it sees a `DelegationDetected` insight, and the action is to review the handoff, not to check a start-state contract before the handoff.

The closest existing catalog is the CLI agent registry, not a start-state table. `AgentRegistry` (`impulse-rs/impulse-ops/src/agent_registry.rs:231`) is an ordered catalog of `AgentDescriptor` (`agent_registry.rs:182`) records that publish a platform id, label, launch command, invocation args, aliases, `AgentCapabilities` (`agent_registry.rs:162`, currently `uses_xml_context` and `startup_delay_ms` only), and `runtime_capabilities`. Those runtime capabilities are "trusted code-declared adapter metadata" (`agent_registry.rs:342`) used for launch authorization. `AgentRegistry::evaluate_role_compatibility` (`agent_registry.rs:475`) and `evaluate_role_compatibility` (`impulse-rs/impulse-ops/src/role_assignment.rs:283`) compare a product role's launch-capability requirements with that declared support; the desktop launch preflight (`impulse-rs/impulse-desktop/src/ui.rs:1168-1219`) calls that check before a governed spawn can reach the host bridge. None of those surfaces publishes or checks the start states a worker will accept for a step handoff.

Any later work on this idea belongs in Ion or the coordinator (or, for launch-time contracts, the CLI catalog), stays held, and does not merge with the rounds field, the cheapest-within-margin report, cost logging on each pick, the loop-164 pairwise disagreement / oracle gap pre-check, the per-subtask quality-cost table, or the loop-165 newly_passed / newly_failed counts already on the held selector_baselines branch.

## 2. Solve Vision with Code (2611.34813): no fit for the picker; routing by task type would make it a content router

The row asks `decide_step_model` to send computable visual tasks to a coding agent rather than a generator. The picker has no task-type input. `decide_step_model` (`impulse-rs/src/agent/step_model.rs:120`) takes only `&HarnessStepContext` and the configured model name. `HarnessStepContext` (`step_model.rs:23-33`) carries actor, review state, latest verification, tool round, current model, and an optional escalate model. The portable `StepModelContext` (`impulse-rs/impulse-step-model/src/lib.rs:44-56`) has the same facts and no task-type, modality, or "computable visual" field. The comment at `step_model.rs:118-119` says cost is unused in v0 and token count is not an input; task type is not an input either. Adding a route that inspects the task and picks a coding agent would make the picker a content router, which stays out of lane. The Game Foundry half is left aside. This does not merge with the rounds field, the cheapest-within-margin report, cost logging on each pick, the loop-164 pairwise disagreement / oracle gap pre-check, the per-subtask quality-cost table, or the loop-165 regression counts.

## 3. What a Forecasting Leaderboard Can Establish / Vernier (2611.31619): partial fit, evaluation only; merges with the held cheapest-within-margin report

This is a qualification report in `selector_baselines`, not a change to `decide_step_model`. The live picker does not rank models, so a leaderboard gap cannot move a pick today. In the example, `best_fixed` (`impulse-rs/impulse-step-model/examples/selector_baselines.rs:74`, identical on main 921f5c9) picks the highest train pass rate and uses lower total cost only to break an exact tie, then name (`selector_baselines.rs:88-89`). Latency is reported (`p50_ms` and `p95_ms` at lines 41-42 and 68-69) but never used in the choice. A model one point better at much higher cost still wins. That is the gap Vernier points at: a rank or score gap smaller than the board's resolution is not evidence, and should not change a routing choice.

That rule merges with held item (b), the cheapest-within-margin report with a Wilson lower bound and a latency tie-break. The held report already asked to treat close pass rates as tied (using the Wilson lower bound from the Loop 159 note so small samples do not fake a lead), then prefer the cheaper model, then lower p50 latency (Loop 163). Vernier's resolution check is the "do not move a choice on an unresolvable gap" half of that same report. This note does not treat Vernier's exact formula (computed from published per-dataset scores, per the abstract) as the same as the Wilson bound; AIden read the abstract only. Either can set the margin later. The work stays held for Jim behind the open selector_baselines branch.

This does not merge with the rounds field or with cost logging on each pick. It is also not the same work as the loop-164 pairwise disagreement / oracle gap pre-check (whether the pool disagrees enough to route at all) or the loop-165 newly_passed / newly_failed counts already written on `grok/selector-baselines-regressions-20261116` at 4644ca6 (`compare_against_reference` at `selector_baselines.rs:85` on that commit). Those later reports can live in the same example. They answer different questions: disagreement and per-task flips, not whether an aggregate gap is resolvable.

No code changed. All evaluation follow-ups stay held for Jim behind the open selector_baselines branch.
