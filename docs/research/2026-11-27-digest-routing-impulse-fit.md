## 1. DecisionReplay (2611.34627): partial fit, evaluation only; companion to the durable step-log question

This row asks Impulse to replay a routing policy offline on logged calls before changing a `decide_step_model` pick. That is already what `selector_baselines` does for fixture runs. The example header says it is evaluation only: it reads recorded `Run` records and never calls or changes `decide_step_model` (`impulse-rs/impulse-step-model/examples/selector_baselines.rs:1-3`, identical on main 921f5c9). `evaluate` compares the current selector, a single `best_fixed` model (`selector_baselines.rs:74`), and choose-at-start on the test split. The held branch `grok/selector-baselines-regressions-20261116` at 4644ca6 adds `compare_against_reference` (`selector_baselines.rs:85` on that commit) so a candidate policy is scored by `newly_passed` and `newly_failed` counts before it would replace a reference pick.

What DecisionReplay describes beyond that is a corpus of logged production calls, with per-option probabilities, tokens, billed cost, and latency, plus a deterministic simulator that can replay select, combine, and cascade policies without new model calls. Impulse does not have that corpus. `StepModelRecord` (`impulse-rs/src/agent/step_model.rs:38`) is logged only through `tracing::info!` (`step_model.rs:155`); the comment at lines 35-36 says durable ledger attachment is later work, and there is no durable store. There are therefore no logged production calls to replay. Replay today is over the example's fixture `Run` records (`selector_baselines.rs:23`: task_id, split, category, policy, pass, cost_usd, latency_ms). Those records have no per-option probabilities, no token counts, and no rounds field.

This does not change `decide_step_model` (`step_model.rs:120`). A richer offline replay, or a production call corpus, belongs in `selector_baselines`. Putting a learned, ensemble, or cascade router into the picker would take it out of lane. The paper's own talking point, still only from the abstract, is to pick one good model per task before building a router.

Held-item merge: this does not merge with (a) the rounds field, or with (b) the cheapest-within-margin report with a Wilson lower bound and a Vernier resolution check. Those are later reports that can live in the same example. Rounds would enrich the `Run` records already being replayed; the margin report decides how to break close scores, which is a different question from replaying a policy on logged calls. Held item (c), logging cost on each pick, is a companion field, not a substitute: DecisionReplay's corpus includes billed cost per call, and cost on `StepModelRecord` would be one production-side input to a later durable log. The durable step-log question is the main companion. Without a durable store of logged calls, there is nothing production-side to replay, so DecisionReplay-style replay on real Impulse calls stays behind that held decision. All of this stays held for Jim behind the open selector_baselines branch.

## 2. OpenAI usage policies, model-access intermediaries: no fit for the picker; policy note only

This is not a change to `decide_step_model` or to `selector_baselines`. The official Usage Policies page, read on November 27, 2026, is dated Effective: November 20, 2026, which matches the digest row. Under the heading "Providing access to our models," the page says:

"If you operate a model-access intermediary platform or other service that enables third parties to directly access OpenAI models, you must obtain our prior review and approval. This requirement does not apply solely because an application integrates OpenAI models to power its features or functionality."

The changelog entry dated 2026-10-21 says the update "sets out approval requirements for national security and law enforcement uses, as well as for model-access intermediaries. These changes are effective November 20, 2026." That language and date were verified on the live page.

Impulse reaches OpenAI as a client, not as a service that sells or proxies access. `OpenAiProvider` (`impulse-rs/src/llm_backends/anthropic.rs:926` at 2ba676d, line 1313 on main 921f5c9) sends `ChatRequest` to `/v1/chat/completions` on `https://api.openai.com` by default, or on `OPENAI_BASE_URL` (`OPENAI_DEFAULT_BASE_URL` at line 37 at 2ba676d, line 105 on main; `OPENAI_BASE_URL_ENV` at line 49 at 2ba676d, line 116 on main). The key comes from `ImpulseProvider::resolve_api_key` (`impulse-rs/src/agent/mod.rs:103` at 2ba676d, line 109 on main), which uses a configured key or the `OPENAI_API_KEY` environment variable (line 114 at 2ba676d, line 120 on main). `build_provider` (`impulse-rs/src/llm_backends/mod.rs:276` at 2ba676d, line 296 on main) constructs `OpenAiProvider` when the selected provider is OpenAI. `ChatRequest` (`llm_backends/mod.rs:137`, identical on main) is an in-process request struct, not an externally advertised HTTP schema.

There is no HTTP server that proxies `ChatRequest` so third parties can call OpenAI models through Impulse. The daemon is a local Unix-socket process (`impulse-rs/src/daemon/mod.rs`); `Daemon::start` binds a `UnixListener` to the configured socket path, not a public TCP port. The daemon `handle_chat_request` path (`impulse-rs/src/daemon/handlers.rs:1446` at 2ba676d, line 1479 on main) uses `AnthropicProvider` and `ANTHROPIC_API_KEY`, not OpenAI. The MCP server and the voice server bind `127.0.0.1` and expose tools, resources, or voice webhooks (`impulse-rs/src/mcp/server.rs:90-91`, same bind on main), not an OpenAI chat proxy. A base-URL override can point the OpenAI client at another origin, including in tests at OpenRouter; that is still Impulse acting as a client of a configured endpoint with the operator's key.

Impulse as used today, with Jim's own keys and for Jim's own use, does not look like a model-access intermediary under that clause. It looks like an application that integrates OpenAI models to power its own features, which the policy says does not by itself require prior approval. This is not legal advice, and nobody has asked OpenAI whether any later hosted form would count. The flag for Jim is only if Impulse is ever shared or hosted so third parties can directly access OpenAI models through it. No code changes follow from this row.
