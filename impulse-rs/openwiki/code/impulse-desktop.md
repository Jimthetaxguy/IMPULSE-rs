# impulse-desktop

Active Dioxus cockpit and typed desktop-host contract for Impulse. (impulse-desktop/README.md:3)

## Ownership

| Layer | Owner |
| --- | --- |
| Layout, rails, inspectors, command palette, review/apply surfaces | Dioxus |
| Native window/process/IPC boundary | Dioxus desktop host adapters |
| PTY lifecycle and live terminal bytes | `DesktopRuntime` / `impulse-term` |
| Reconciled agents, context, memory, artifacts, and interventions | Impulse daemon |
| Terminal glyph rendering | xterm.js |
| Menu bar, panels, notifications, accessibility hooks | Native island bridge |
| Built-in MCP tools and connector status | Rust runtime snapshots surfaced to Dioxus |

Source: (impulse-desktop/README.md:18-26)

Native islands must publish serializable DTOs back to Dioxus. (impulse-desktop/README.md:28-29)
They must not keep independent copies of sessions, memory, terminal state, or artifacts. (impulse-desktop/README.md:28-29)

## Runtime Contracts

- `WorkspaceTarget` names the cwd/project root in which an agent process starts. The runtime derives it from `cwd` when the UI does not provide richer metadata. This targeting is not a filesystem sandbox or authorization boundary; structural enforcement depends on the selected runtime or sandbox. (impulse-desktop/README.md:33-36)
- `AgentSpawnRequest` carries platform, command, workspace, terminal dimensions, and optional MCP tool descriptors. (impulse-desktop/README.md:37-38)
- `AgentRuntimeSnapshot` is the desktop's local PTY fact model: focused state, process status, workspace, output metrics, and built-in Rust MCP tools. (impulse-desktop/README.md:39-40)

## Features

- `desktop-app` enables the real Dioxus Desktop binary target: `cargo run -p impulse-desktop --features desktop-app --bin impulse-desktop`. The binary installs the live Dioxus eval bridge behind `window.__IMPULSE_DESKTOP_HOST`, starts the daemon-ops publisher/subscriber, and reports subscription freshness separately from telemetry publish health. (impulse-desktop/README.md:77-81)
- `native-macos` enables the Objective-C/AppKit compatibility bridge via `objc2`. (impulse-desktop/README.md:82-83)
- `legacy-tauri-runtime` enables the compatibility Tauri command annotations without making Tauri a hard dependency of the default workspace check. (impulse-desktop/README.md:84-85)

## Visual And Host Smoke

Before running the visual smoke, `npm run vendor:xterm` copies the pinned `@xterm/xterm` and `@xterm/addon-fit` browser assets into `assets/vendor/xterm/`. (impulse-desktop/README.md:91-95)
The Dioxus shell declares those local files with `data-impulse-terminal-asset` tags, and the host contract resolves the same relative paths instead of a CDN. (impulse-desktop/README.md:91-95)

The visual smoke renders static Dioxus SSR fixtures for each `DesktopView`, then opens them in headless Chromium to assert non-blank layout, no shell overlap, no viewport overflow, route-specific visible content, local xterm globals, and no remote font or terminal asset URLs. (impulse-desktop/README.md:97-100)

## src

`discover` — Resolve the daemon socket without conflating the desktop's global memory fallback with the daemon's project-local default. (impulse-desktop/src/daemon_ops.rs:54-97)
`agent_runtime_from_snapshot` — Complete conversion from desktop PTY facts to the daemon's telemetry DTO. (impulse-desktop/src/daemon_ops.rs:145-204)
`attach_desktop_daemon_ops` — Wrap the UI event sink with the daemon-truth publisher/subscriber. (impulse-desktop/src/daemon_ops.rs:2881-2898)
`dispatch_host_invoke` — Dispatch a single `invoke` request, always producing a response addressed to the same `id` (success or error). Never panics. (impulse-desktop/src/host_bridge.rs:159-170)
`host_event_envelope` — Build the `host_event` envelope delivered to JS `listen` handlers. The payload is the event's `data` content so handlers receive the same shape the legacy Tauri host produced (e.g. `{ agent_id, data }` for terminal output). (impulse-desktop/src/host_bridge.rs:185-198)
`channel_event_sink` — Create a [`ChannelEventSink`] paired with its receiver. Wire the sink into [`crate::runtime::DesktopRuntimeBuilder::with_event_sink`] and hand the receiver to [`LiveHostContext`]. (impulse-desktop/src/host_bridge.rs:215-221)
`governed_task_mutate` — Acknowledged governed-task mutation. The Unix request is blocking, so the host runs it on Tokio's blocking pool rather than the Dioxus async worker. (impulse-desktop/src/host_commands.rs:145-154)
`agent_platforms` — Return the runtime registry's open platform catalog for launcher rendering. Registry parse failures are surfaced to the host instead of silently falling back to a hard-coded list. (impulse-desktop/src/host_commands.rs:270-278)
`mcp_invoke` — Host command — invoke a built-in MCP tool by name. The command surface is the same with or without the `legacy-tauri-runtime` feature: when the legacy adapter is enabled the function gets `tauri::State`; otherwise it takes a borrowed reference so SSR tests and pure-Rust callers can exercise the same command body. (impulse-desktop/src/host_commands.rs:537-550)
`with_builtins` — Build a registry pre-loaded with eight built-ins: the six documented ones (`impulse.agent_spawn`, `impulse.agent_write`, `impulse.search_memory`, `impulse.review_injection`, `impulse.review_decision`, `impulse.project_context`) wired to their real bodies, plus two read-only helpers (`impulse.list_workspaces`, `impulse.list_agents`). (impulse-desktop/src/mcp.rs:284-304)
`format_relative_age` — Render a human-readable relative age from a past unix-millis timestamp `ms` against a `now_ms` reference (e.g. "just now", "5m ago", "2h ago", "3d ago"). (impulse-desktop/src/theme.rs:66-93)
`usage_meter_pct` — Clamp a `0.0..=1.0` usage fraction to an integer percentage in `0..=100`. (impulse-desktop/src/theme.rs:95-104)
